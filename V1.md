# OCRCheckup — Technical Design Document

## 1) Context

OCRCheckup is a simple, trustworthy, and extensible framework for evaluating **scene text recognition** (STR) models. It powers:

* Clear, comparable results (“best overall,” “best value”) using a fixed, shared dataset (initially **10 domains × 10 samples**).
* An opinionated, reproducible pipeline that separates **prediction** from **evaluation**.
* A first‑class **Variant** concept that captures everything that can change outputs or cost (e.g., prompts, recognizer settings, execution path).

Primary consumers are engineers and low‑code developers who want quick, credible answers; secondary consumers are downstream properties (leaderboard site, blog).

---

## 2) Scope

**In scope**

* Task: **recognition only** (cropped words/lines), not detection.
* Dataset: existing **10×10** set; dataset curation out of scope.
* Normalization rules:

  * Lowercase
  * Collapse any whitespace to a single space
  * Remove punctuation
  * Labeler judgment on edge cases (documented examples)
* Metrics:

  * **Accuracy** (NED%, i.e., 100 × (1 − edit_distance/len(gt)))
  * **Correctness** (EMR: exact match after normalization)
  * **CostUSD** (required; per‑sample cost)
* Two-phase pipeline: **Predict → Evaluate**.
* File outputs: **JSONL** for predictions and evaluations; dataset manifest in **JSON**.

**Out of scope (now)**

* Preprocessing pipelines, decoding strategy tuning, latency/stability leaderboards, aggregation/visualization (handled by the separate leaderboard project), databases (e.g., SQLite).

## 3) Core Concepts

### 3.1 Dataset hierarchy (one‑way ownership)

* **Dataset** → array of **Domain** → array of **Sample**.
* Each object carries **only its own ID** (no cross‑refs in the files).
* At runtime we build an **in‑memory index**: `sample_id → (domain_id, Sample)` for convenience.
  *Why:* keeps on-disk format minimal; preserves the simple, one‑way ownership pattern.

### 3.2 ModelFamily (schema owner)

A **ModelFamily** defines the *field schema and canonicalization* for variants that belong to that family.

* `family_id` (e.g., `tesseract`, `paddleocr`, `openai-vlm`)
* `display_name`
* `description?`
* `fields_schema` (Pydantic model): validates and canonicalizes **Variant.fields** for this family
* `family_schema_version`: version of the schema/canonicalization (included in variant hashing)

*Why:* Families give us a strict, typed place to validate knobs like `lang`, `psm`, or `prompt` without forcing unrelated fields on other families.

> Relationship choice: **Variants reference families (one‑way)**. We do **not** store a `variants[]` list inside a family. This keeps families stateless schema providers and avoids cross‑object churn.

### 3.3 Adapter (execution owner)

An **Adapter** is the execution mechanism for running a Variant on a Sample (e.g., Tesseract local CLI, PaddleOCR Python, OpenAI HTTP).

* `id` (e.g., `tesseract-cli`, `paddleocr-py`, `openai-http`)
* `description?`
* `run(variant, sample) -> AdapterOutput`

  * Returns **only**:

    * `prediction` (string)
    * `metadata` (free‑form dict; adapter decides structure)

*Why:* Adapters focus purely on “how to run” and emit raw metadata. No timing obligations, no global schema constraints.

### 3.4 PricingModel (cost owner; required)

A **PricingModel** converts a prediction’s context into **CostUSD**.

* `id` (e.g., `local`, `flat-per-image`, `openai-2025-10`, `gcv-2025-10`)
* `description?`
* `quote(prediction_record, variant, config?) -> float | None`

*Why:* Cost changes over time and across providers. Pricing is computed **in evaluation**, not baked into predictions. There is **no field‑mapping requirement**; pricing code can read whatever it needs from `prediction_record.metadata` and `variant`.

### 3.5 Variant (first‑class, fully specified)

A **Variant** says “run this family with these fields via this adapter, and price it with this model.”

* `variant_id?` (computed; see hashing)
* `name`
* `description?`
* `family_id` (links to ModelFamily for field validation)
* `fields` (dict; family validates/canonicalizes; if you want to track provider’s model version, include it here, e.g., `{"model_name": "...", "model_version": "..."}`)
* `adapter`:

  * `id`
  * `config?` (dict; adapter-specific)
* `pricing`:

  * `id`
  * `config?` (dict; pricing‑specific)

*Why:* Everything affecting output/cost is inside the Variant. We removed a top‑level `model_version`; if needed, it lives in `fields`.

**Variant hashing (identity)**
Hash over a sorted JSON of:

* `family_id`
* `family_schema_version`
* **canonical** `fields` (via family schema)
* `adapter.id` and a **sanitized** `adapter.config` (see security)
* `pricing.id` and a **sanitized** `pricing.config`

> Each Adapter and PricingModel exposes `hash_config(config) -> dict` to strip secrets and non‑deterministic keys before hashing. If absent, default is an empty dict to avoid leaking secrets.

### 3.6 Normalizer (versioned rules)

Applies deterministic text normalization for metrics:

* `unicode_form` (e.g., NFC)
* `lowercase` (bool)
* `collapse_whitespace` (bool)
* `remove_punctuation` (bool)
* `spec_version`
* `description?`
* `normalize(text) -> text`
* `id() -> hash(spec)`

### 3.7 Evaluators (metric owners)

Pluggable components that compute metrics from GT + prediction.

* `metric_name: "accuracy" | "correctness" | "cost_usd" | ...`
* `evaluate(gt_raw, pred_raw, *, normalizer, prediction_record, variant) -> Any`

**Built‑ins**

* **Accuracy** (NED% float)
* **Correctness** (EMR int 0/1)
* **CostUSD** (float or `None`), implemented via the Variant’s **PricingModel**

### 3.8 Runs and Records

* **PredictionRun**: one Variant across the **whole dataset** (always); maintains shuffle/seed; handles timing.
* **PredictionRecord (JSONL)**: immutable per‑sample outputs.
* **EvaluationRun**: applies Normalizer + Evaluators to a PredictionRun.
* **EvaluationRecord (JSONL)**: per‑sample metrics.

## 4) Core Flow

1. **Configure in Python**

   * Register your **ModelFamily**, **Adapter**, **PricingModel** (small registries keyed by `id`).
   * Construct a **Variant** (with adapter + pricing objects/IDs and configs) and validate `fields` through the family’s schema; compute `variant_id`.

2. **Predict (Phase A)**

   * Load **Dataset** (from JSON or constructed in code); build in‑memory `sample_index`.
   * Create **PredictionRun** (shuffle samples by seed).
   * For each sample:

     * `start = now()`
     * `Adapter.run(variant, sample) → {prediction, metadata}`
     * `end = now()`
     * Write **PredictionRecord** line with:

       * `run_id`, `variant_id`, `sample_id`
       * `prediction_raw = prediction`
       * `started_at = start`, `ended_at = end`
       * `metadata` (exactly what adapter returned)
       * `error = null | "reason"`
   * Output: `runs/<run_id>.jsonl`

3. **Evaluate (Phase B)**

   * Create **EvaluationRun** with Normalizer and chosen Evaluators (must include CostUSD).
   * For each **PredictionRecord**:

     * Look up GT via `sample_id` from the Dataset index.
     * Compute `gt_norm = normalize(gt_raw)`, `pred_norm = normalize(pred_raw)`.
     * Compute:

       * **Accuracy (NED%)**
       * **Correctness (EMR)**
       * **CostUSD** via `PricingModel.quote(record, variant, pricing.config)`
         (Pricing model reads whatever it needs from `record.metadata` and `variant`; no field mapping required.)
     * Write **EvaluationRecord** line with metric key/value pairs.
   * Output: `evals/<evaluation_id>.jsonl`

> Aggregation/leaderboards are deliberately out of scope for OCRCheckup; another project ingests these JSONLs.

## 5) Schemas (objects, types, functions)

> Types are expressed as Python-esque type hints for clarity. Persistence uses JSON/JSONL only.

### 5.1 Dataset, Domain, Sample (JSON)

**Dataset**

```text
dataset_id: str
name: str
description?: str
domains: Domain[]
```

**Domain**

```text
domain_id: str
name: str
description?: str
samples: Sample[]
```

**Sample**

```text
sample_id: str
image_uri: str
ground_truth_raw: str
```

**Runtime helper (not serialized)**

```text
sample_index: Dict[sample_id, (domain_id, Sample)]
```

### 5.2 ModelFamily (Python)

```text
family_id: str
display_name: str
description?: str
fields_schema: PydanticModel           # validates + canonicalizes Variant.fields
family_schema_version: str             # included in variant hashing
```

**Functions**

```text
validate_fields(fields: dict) -> dict   # raises on invalid; returns canonical dict
```

### 5.3 Adapter (Python)

```text
id: str
description?: str

run(variant: Variant, sample: Sample) -> AdapterOutput
hash_config(config: dict) -> dict       # optional; returns sanitized subset for hashing
```

**AdapterOutput (Python object, not persisted directly)**

```text
prediction: str
metadata: dict                          # free‑form; adapter decides the shape
```

### 5.4 PricingModel (Python; **required**)

```text
id: str
description?: str

quote(prediction_record: PredictionRecord, variant: Variant, config?: dict) -> float | None
hash_config(config: dict) -> dict       # optional; sanitize for hashing
```

### 5.5 Variant (Python → serialized to JSON inside runs)

```text
variant_id?: str                        # computed
name: str
description?: str
family_id: str
fields: dict                            # validated/canonicalized by family
adapter:
  id: str
  config?: dict
pricing:
  id: str
  config?: dict
```

**Functions**

```text
compute_variant_id(self, family_schema_version: str, adapter_hash_cfg: dict, pricing_hash_cfg: dict) -> str
```

**Hash inputs**

* `family_id`, `family_schema_version`
* canonical `fields`
* `adapter.id`, sanitized `adapter.config`
* `pricing.id`, sanitized `pricing.config`

### 5.6 Normalizer (Python)

```text
spec:
  unicode_form: Literal["NFC","NFD","NFKC","NFKD"]
  lowercase: bool
  collapse_whitespace: bool
  remove_punctuation: bool
  spec_version: str
  description?: str

normalize(text: str) -> str
id() -> str   # hash over spec
```

### 5.7 Evaluators (Python)

```text
metric_name: str
evaluate(
  gt_raw: str,
  pred_raw: str,
  *,
  normalizer: Normalizer,
  prediction_record: PredictionRecord,
  variant: Variant
) -> Any
```

**Built‑ins**

* `Accuracy` (NED%: float)
* `Correctness` (EMR: int)
* `CostUSD` (float|None) — uses `variant.pricing`

### 5.8 PredictionRun (Python; persisted only via per‑sample records)

```text
run_id: str
dataset_id: str
variant: Variant
seed: int
shuffled: Literal[True]                 # always true
created_at: ISO-8601 string
```

**Runner behavior**

* Iterates all samples in the dataset (whole dataset, by design).
* For each sample:

  * measure `started_at`/`ended_at` around `Adapter.run(...)`
  * construct & persist **PredictionRecord**

### 5.9 PredictionRecord (JSONL; one per line)

```text
run_id: str
variant_id: str
sample_id: str
prediction_raw: str
started_at: ISO-8601 string
ended_at: ISO-8601 string
metadata: dict                          # free‑form; as returned by Adapter
error: str | null
```

> Elapsed time is intentionally **not** stored; evaluators can compute it from start/end if needed.

### 5.10 EvaluationRun (Python; persisted only via per‑sample records)

```text
evaluation_id: str
run_id: str
normalizer: Normalizer
evaluators: List[Evaluator]             # must include CostUSD
```

### 5.11 EvaluationRecord (JSONL; one per line)

```text
evaluation_id: str
run_id: str
variant_id: str
sample_id: str
gt_norm: str
pred_norm: str
metrics: Dict[str, Any]                 # e.g., {"accuracy": 92.1, "correctness": 1, "cost_usd": 0.0031}
```

---

## 6) Formats & “where things live”

* **Python** (control plane): define/instantiate `ModelFamily`, `Variant` (with `adapter` + `pricing` objects/ids), `Adapter`, `PricingModel`, `Normalizer`, `Evaluators`, and run the pipeline.

  * In code you may **hold direct object references** (adapters/pricing instances).
  * For persistence, OCRCheckup serializes **IDs + configs** (never objects) into records.

* **JSON**: dataset manifest (hierarchical file with dataset/domains/samples).

* **JSONL**: append‑only logs:

  * `PredictionRecord` per sample
  * `EvaluationRecord` per sample

* **No YAML** in OCRCheckup. (A CLI wrapper can be added later; it would load Python modules or JSON manifests.)
