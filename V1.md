# OCRCheckup — Technical Design Document

## 0) Meta
Only ever modify this file with fundamental design changes to the core structure outlined here. You are NEVER to update this file with ephemeral content including, but not limited to: Changelogs, "Planned" notes, "Currently building", date-specific info, specific model implementation information, etc.

## 1) Context

OCRCheckup is a simple, trustworthy, and extensible framework for evaluating **scene text recognition** (STR) models. It powers:

* Clear, comparable results (“best overall,” “best value”) using a fixed, shared dataset (initially **10 domains × 10 samples**).
* An opinionated, reproducible pipeline that separates **prediction** from **evaluation**.
* A first‑class **Variant** concept that captures everything that can change outputs or cost (e.g., prompts, recognizer settings, execution path).

Primary consumers are engineers and low‑code developers who want quick, credible answers; secondary consumers are downstream properties (leaderboard site, blog).

---

## 2) Scope

**In scope**

* Task: **recognition only** (cropped words/lines), not detection.
* Dataset: existing **10×10** set; dataset curation out of scope.
* Normalization rules:

  * Lowercase
  * Collapse any whitespace to a single space
  * Remove punctuation
  * Labeler judgment on edge cases (documented examples)
* Metrics:

  * **Accuracy** (NED%, i.e., 100 × (1 − edit_distance/len(gt)))
  * **Correctness** (EMR: exact match after normalization)
  * **CostUSD** (required; per‑sample cost)
* Two-phase pipeline: **Predict → Evaluate**.
* File outputs: **JSONL** for predictions and evaluations; dataset manifest in **JSON**.

**Out of scope (now)**

* Preprocessing pipelines, decoding strategy tuning, latency/stability leaderboards, aggregation/visualization (handled by the separate leaderboard project), databases (e.g., SQLite).

## 3) Core Concepts

### 3.1 Dataset hierarchy (one‑way ownership)

* **Dataset** → array of **Domain** → array of **Sample**.
* Each object carries **only its own ID** (no cross‑refs in the files).
* At runtime we build an **in‑memory index**: `sample_id → (domain_id, Sample)` for convenience.
  *Why:* keeps on-disk format minimal; preserves the simple, one‑way ownership pattern.

### 3.2 ModelFamily (schema owner)

A **ModelFamily** defines the *field schema and canonicalization* for variants that belong to that family.

* `family_id` (e.g., `tesseract`, `paddleocr`, `openai-gpt-4o`)
* `display_name`
* `description?`
* `fields_schema` (Pydantic model): validates and canonicalizes **Variant.fields** for this family
* `family_schema_version`: version of the schema/canonicalization (included in variant hashing)

*Why:* Families give us a strict, typed place to validate knobs like `lang`, `psm`, `prompt`, or provider‑specific checkpoints (`snapshot`/`model_version`/`version`) without forcing unrelated fields on other families.

> Relationship choice: **Variants reference families (one‑way)**. We do **not** store a `variants[]` list inside a family. This keeps families stateless schema providers and avoids cross‑object churn.

**Example: ModelFamily with field schema**

```python
from typing import Literal
from pydantic import BaseModel, Field
from ocrcheckup.families.base import ModelFamily

class GPT4oFields(BaseModel):
    snapshot: str = Field(default="gpt-4o-2024-05-13")
    prompt: str | None = None
    image_detail: Literal["low", "high"] | None = Field(default="high")

class GPT4oFamily:
    family_id = "openai-gpt-4o"
    display_name = "OpenAI GPT-4o"
    family_schema_version = "1"
    fields_schema = GPT4oFields
    
    def validate_fields(self, fields: dict) -> dict:
        return GPT4oFields.model_validate(fields).model_dump(
            mode="json", exclude_none=True
        )
```

Note: `family_schema_version` is a string you bump whenever you change this family's field schema or its canonicalization behavior. It is included in the variant hash so historical variants remain stable across schema changes (e.g., `"1"`, `"2"`).

Provider field naming guidance
- OpenAI (GPT‑4o/4o‑mini/4.5) use `snapshot` (e.g., `gpt-4o-2024-05-13`).
- Google Gemini use `model_version` (e.g., `gemini-1.5-pro`).
- Anthropic Claude use `version` (e.g., `claude-3-5-haiku-20241022`).

### 3.3 Adapter (execution owner)

An **Adapter** is the execution mechanism for running a Variant on a Sample (e.g., Tesseract local CLI, PaddleOCR Python, OpenAI HTTP).

* `id` (e.g., `tesseract-cli`, `paddleocr-py`, `openai-http`)
* `description?`
* `setup() -> None` (optional lifecycle hook; see below)
* `run(variant, sample) -> AdapterOutput`

  * Returns **only**:

    * `prediction` (string)
    * `metadata` (free‑form dict; adapter decides structure)

*Why:* Adapters focus purely on “how to run” and emit raw metadata. No timing obligations, no global schema constraints.

**Lifecycle**

Adapters may perform expensive initialization (API clients, model weights, warmups) either during instantiation or inside an optional `setup()` method. The prediction runner calls `setup()` once before iterating samples. Only `run()` invocations are timed for metrics and logged timestamps; initialization/warmup is excluded from per-sample timing.

**Example: Adapter with setup()**

```python
from ocrcheckup.adapters.base import Adapter, AdapterOutput
from ocrcheckup.core.types import Sample
from ocrcheckup.core.variant import Variant
from transformers import AutoModelForCausalLM

class LocalLLMAdapter:
    id = "local-llm"
    description = "Local HuggingFace model"
    
    def __init__(self, model_name: str):
        self.model_name = model_name
        self.model = None  # Loaded in setup()
    
    def setup(self) -> None:
        """Load model weights once before prediction loop."""
        self.model = AutoModelForCausalLM.from_pretrained(self.model_name)
        self.model.eval()
    
    def run(self, variant: Variant, sample: Sample) -> AdapterOutput:
        # Use self.model for inference
        prediction = self.model.generate(...)
        return AdapterOutput(
            prediction=prediction,
            metadata={"model": self.model_name}
        )
```

**Example: Simple adapter without setup()**

```python
class SimpleHTTPAdapter:
    id = "simple-http"
    
    def run(self, variant: Variant, sample: Sample) -> AdapterOutput:
        # No setup needed; client created on-demand
        response = requests.post(url, data=...)
        return AdapterOutput(
            prediction=response.text,
            metadata={"status_code": response.status_code}
        )
```

### 3.4 PricingModel (cost owner; required)

A **PricingModel** converts a prediction's context into **CostUSD**.

* `id` (e.g., `local`, `flat-per-image`, `openai`, `anthropic`, `gemini`)
* `description?`
* `quote(prediction_record, variant, config?) -> float | None`

*Why:* Cost changes over time and across providers. Pricing is computed **in evaluation**, not baked into predictions. There is **no field‑mapping requirement**; pricing code can read whatever it needs from `prediction_record.metadata` and `variant`.

**Example: Provider-specific pricing model**

```python
from ocrcheckup.pricing.base import PricingModel
from ocrcheckup.core.variant import Variant

class OpenAIPricing:
    id = "openai"
    description = "OpenAI token-based pricing"
    
    # Per-model pricing rates (USD per 1K tokens)
    RATES = {
        "gpt-4o-2024-05-13": {"input": 2.50, "output": 10.00},
        "gpt-4o-mini-2024-07-18": {"input": 0.15, "output": 0.60},
    }
    
    def quote(self, prediction_record: dict, variant: Variant, config: dict | None) -> float | None:
        metadata = prediction_record.get("metadata", {})
        snapshot = variant.fields.get("snapshot", "")
        input_tokens = metadata.get("input_tokens", 0)
        output_tokens = metadata.get("output_tokens", 0)
        
        if snapshot not in self.RATES:
            return None
        
        rates = self.RATES[snapshot]
        cost = (input_tokens / 1000 * rates["input"]) + (output_tokens / 1000 * rates["output"])
        return cost
```

### 3.5 Variant (first‑class, fully specified)

A **Variant** says “run this family with these fields via this adapter, and price it with this model.”

* `variant_id?` (computed; see hashing)
* `name`
* `description?`
* `family_id` (links to ModelFamily for field validation)
* `fields` (dict; family validates/canonicalizes; if you want to track provider’s model version, include it here, e.g., `{"model_name": "...", "model_version": "..."}`)
* `adapter`:

  * `id`
  * `config?` (dict; adapter-specific)
* `pricing`:

  * `id`
  * `config?` (dict; pricing‑specific)

*Why:* Everything affecting output/cost is inside the Variant. We removed a top‑level `model_version`; if needed, it lives in `fields`.

**Variant hashing (identity)**
Hash over a sorted JSON of:

* `family_id`
* `family_schema_version`
* **canonical** `fields` (via family schema)
* `adapter.id` and a **sanitized** `adapter.config` (see security)
* `pricing.id` and a **sanitized** `pricing.config`

> Each Adapter and PricingModel exposes `hash_config(config) -> dict` to strip secrets and non‑deterministic keys before hashing. If absent, default is an empty dict to avoid leaking secrets.

### 3.6 Normalizer (versioned rules)

Applies deterministic text normalization for metrics:

* `unicode_form` (e.g., NFC)
* `lowercase` (bool)
* `collapse_whitespace` (bool)
* `remove_punctuation` (bool)
* `spec_version`
* `description?`
* `normalize(text) -> text`
* `id() -> hash(spec)`

### 3.7 Evaluators (metric owners)

Pluggable components that compute metrics from GT + prediction.

* `metric_name: "accuracy" | "correctness" | "cost_usd" | ...`
* `evaluate(gt_raw, pred_raw, *, normalizer, prediction_record, variant) -> Any`

**Built‑ins**

* **Accuracy** (NED% float)
* **Correctness** (EMR int 0/1)
* **CostUSD** (float or `None`), implemented via the Variant’s **PricingModel**

### 3.8 Runs and Records

* **PredictionRun**: one Variant across the **whole dataset** (always); maintains shuffle/seed; handles timing.
* **PredictionRecord (JSONL)**: immutable per‑sample outputs.
* **EvaluationRun**: applies Normalizer + Evaluators to a PredictionRun.
* **EvaluationRecord (JSONL)**: per‑sample metrics.

## 4) Core Flow

1. **Configure in Python**

   * Register your **ModelFamily**, **Adapter**, **PricingModel** (small registries keyed by `id`).
   * Construct a **Variant** (with adapter + pricing objects/IDs and configs) and validate `fields` through the family’s schema; compute `variant_id`.

2. **Predict (Phase A)**

   * Load **Dataset** (from JSON or constructed in code); build in‑memory `sample_index`.
   * Create **PredictionRun** (shuffle samples by seed).
   * Look up `variant.adapter`, instantiate or fetch the adapter, and invoke `setup()` once if provided.
   * For each sample:

     * `start = now()`
     * `Adapter.run(variant, sample) → {prediction, metadata}`
     * `end = now()`
     * Write **PredictionRecord** line with:

       * `run_id`, `variant_id`, `sample_id`
       * `prediction_raw = prediction`
       * `started_at = start`, `ended_at = end`
       * `metadata` (exactly what adapter returned)
       * `error = null | "reason"`
   * Output: `runs/<run_id>.jsonl`

   **Example: Prediction runner calling setup()**

   ```python
   adapter = adapters.get(variant.adapter.id)
   if hasattr(adapter, "setup"):
       adapter.setup()  # Called once, not timed
   
   for sample in shuffled_samples:
       started_at = utc_now_iso()
       result = adapter.run(variant, sample)  # Timed
       ended_at = utc_now_iso()
       # Write PredictionRecord...
   ```

3. **Evaluate (Phase B)**

   * Create **EvaluationRun** with Normalizer and chosen Evaluators (must include CostUSD).
   * For each **PredictionRecord**:

     * Look up GT via `sample_id` from the Dataset index.
     * Compute `gt_norm = normalize(gt_raw)`, `pred_norm = normalize(pred_raw)`.
     * Compute:

       * **Accuracy (NED%)**
       * **Correctness (EMR)**
       * **CostUSD** via `PricingModel.quote(record, variant, pricing.config)`
         (Pricing model reads whatever it needs from `record.metadata` and `variant`; no field mapping required.)
     * Write **EvaluationRecord** line with metric key/value pairs.
   * Output: `evals/<evaluation_id>.jsonl`

> Aggregation/leaderboards are deliberately out of scope for OCRCheckup; another project ingests these JSONLs.

> Types are expressed as Python-esque type hints for clarity. Persistence uses JSON/JSONL only.

### 5.1 Dataset, Domain, Sample (JSON)

**Dataset**

```text

description?: str

```

**Domain**

```text

```

**Sample**

```text

```

**Runtime helper (not serialized)**

```text
sample_index: Dict[sample_id, (domain_id, Sample)]
```

### 5.2 ModelFamily (Python)

```text
family_id: str
display_name: str
description?: str
```

**Functions**

```text
validate_fields(fields: dict) -> dict   # raises on invalid; returns canonical dict
```


**AdapterOutput (Python object, not persisted directly)**


```text

description?: str
```

```text
  id: str
  config?: dict

  id: str
  config?: dict
```

```text
compute_variant_id(self, family_schema_version: str, adapter_hash_cfg: dict, pricing_hash_cfg: dict) -> str
```

**Hash inputs**

* `family_id`, `family_schema_version`
* canonical `fields`
* `adapter.id`, sanitized `adapter.config`
* `pricing.id`, sanitized `pricing.config`

### 5.6 Normalizer (Python)

```text

  unicode_form: Literal["NFC","NFD","NFKC","NFKD"]
  lowercase: bool
  collapse_whitespace: bool
  remove_punctuation: bool
  spec_version: str
  description?: str

normalize(text: str) -> str
id() -> str   # hash over spec
```

### 5.7 Evaluators (Python)

```text
metric_name: str
evaluate(
  gt_raw: str,
  pred_raw: str,
  *,
  normalizer: Normalizer,
  prediction_record: PredictionRecord,
  variant: Variant
) -> Any
```

**Built‑ins**

* `Accuracy` (NED%: float)
* `Correctness` (EMR: int)
* `CostUSD` (float|None) — uses `variant.pricing`

### 5.8 PredictionRun (Python; persisted only via per‑sample records)

```text
run_id: str
dataset_id: str
variant: Variant
seed: int
shuffled: Literal[True]                 # always true
created_at: ISO-8601 string
```

**Runner behavior**

* Look up adapter from registry and call `setup()` once if provided (not timed).
* Iterates all samples in the dataset (whole dataset, by design).
* For each sample:

  * measure `started_at`/`ended_at` around `Adapter.run(...)` (only `run()` is timed)
  * construct & persist **PredictionRecord**

### 5.9 PredictionRecord (JSONL; one per line)

```text
run_id: str
variant_id: str
sample_id: str
prediction_raw: str
started_at: ISO-8601 string
ended_at: ISO-8601 string
metadata: dict                          # free‑form; as returned by Adapter
error: str | null
```

> Elapsed time is intentionally **not** stored; evaluators can compute it from start/end if needed.

### 5.10 EvaluationRun (Python; persisted only via per‑sample records)

```text
evaluation_id: str
run_id: str
normalizer: Normalizer
evaluators: List[Evaluator]             # must include CostUSD
```

### 5.11 EvaluationRecord (JSONL; one per line)

```text
evaluation_id: str
run_id: str
variant_id: str
sample_id: str
gt_norm: str
pred_norm: str
metrics: Dict[str, Any]                 # e.g., {"accuracy": 92.1, "correctness": 1, "cost_usd": 0.0031}
```

## 6) Formats & “where things live”

* **Python** (control plane): define/instantiate `ModelFamily`, `Variant` (with `adapter` + `pricing` objects/ids), `Adapter`, `PricingModel`, `Normalizer`, `Evaluators`, and run the pipeline.

  * In code you may **hold direct object references** (adapters/pricing instances).
  * For persistence, OCRCheckup serializes **IDs + configs** (never objects) into records.

* **JSON**: dataset manifest (hierarchical file with dataset/domains/samples).

* **JSONL**: append‑only logs:

  * `PredictionRecord` per sample
  * `EvaluationRecord` per sample

* **No YAML** in OCRCheckup. (A CLI wrapper can be added later; it would load Python modules or JSON manifests.)

## 7) Prompts

Use a single module `prompts.py` to host shared prompt strings. Variants carry the prompt as a direct string in `fields.prompt`. Registration code can expand variants by iterating available prompts — names/IDs are not stored in the variant.

```python
# prompts.py
PROMPTS = {
    "classic": "Read the text in the image. Return only the text as it is visible in the image."
}

def get_all_prompts() -> list[str]:
    return list(PROMPTS.values())
```

Variant construction (registration-time), writing the prompt string directly into fields:

```python
from prompts import get_all_prompts
from ocrcheckup.core.variant import Variant, AdapterRef, PricingRef

base_fields = {"snapshot": "gpt-4o-2024-05-13", "image_detail": "high"}
variants = []
for prompt_text in get_all_prompts():
    fields = {**base_fields, "prompt": prompt_text}
    variants.append(
        Variant(
            name="gpt-4o",
            family_id="openai-gpt-4o",
            fields=fields,
            adapter=AdapterRef(id="openai-http"),
            pricing=PricingRef(id="openai"),
        )
    )
```

Rationale
- Keeps prompts visible and auditable without complicating the Variant schema.
- Multiple prompts can be introduced by only editing `prompts.py` and registration code.
- Variant identity includes the prompt content (via canonical `fields`), ensuring distinct `variant_id`s.

## 8) Runners

Runners execute prediction and evaluation with consistent policies across adapters and families.

Prediction Runner
- Validates and canonicalizes `Variant.fields` via the `ModelFamily`, then computes `variant_id`.
- Retrieves the adapter, invokes `setup()` once, iterates the whole dataset in a deterministic shuffled order (seeded).
- Times only `Adapter.run(...)` per sample; initialization or warmup is not timed.
- Captures exceptions into `PredictionRecord.error`; prediction text becomes empty when errors occur.
- Concurrency, per-sample timeout, and retry policy are configured at the runner level.
- Emits one `PredictionRecord` line per sample under `results/runs/`.

Evaluation Runner
- Reads a run’s JSONL, applies a `Normalizer`, executes Evaluators, and computes CostUSD via the chosen `PricingModel`.
- Emits one `EvaluationRecord` line per sample under `results/evals/`.

Runner configuration (illustrative)
```text
seed: int
shuffle: Literal[True]
max_concurrency: int
per_sample_timeout_s: float
max_retries: int
retry_backoff_s: float
```

## 9) File Structure

A concrete layout that keeps families (schema), adapters (execution), pricing (cost), and DRY bases well-organized:

```text
ocrcheckup/
  adapters/
    base.py
    cloud.py             # HTTP adapters (OpenAI, Anthropic, Gemini, Mistral, Roboflow)
    local/
      tesseract_pytesseract.py
      easyocr.py
      qwen.py
      trocr.py
      idefics.py
      moondream.py
  families/
    base.py
    anthropic.py
    doctr.py
    easyocr.py
    florence2.py
    gemini.py
    idefics.py
    mistral.py
    moondream.py
    openai.py
    qwen.py
    tesseract.py
    trocr.py
  pricing/
    base.py
    providers.py         # OpenAI, Anthropic, Gemini, Mistral, Roboflow pricing
    builtins/
      local.py
      flat_per_image.py
  prompts.py             # PROMPTS = {...}; get_all_prompts()
  runs/
    predict.py
    evaluate.py
  scripts/
    run_variants.py
```

Notes
- Families are narrow (per model line). Checkpoints/preview/prod live in fields named per provider (`snapshot`, `model_version`, `version`) as variants.
- HTTP web adapters are consolidated in a single `adapters/cloud.py`. Local model adapters are per‑model for clarity.
- Pricing is provider-specific and reads usage from adapter metadata.
- Prompts: use `fields.prompt` (string). Provide shared strings in `prompts.py`; resolve at registration time by writing the chosen prompt string into variant fields.
